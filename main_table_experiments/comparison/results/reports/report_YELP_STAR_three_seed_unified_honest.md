# YELP_STAR · 三 seed 结果整理与「统一分析」用法说明

> **更新时间**：2026-05-13（用户要求 **手动停止** `seed=2` 的 `RL_model.py` 之后整理）  
> **数据文件**：`comparison/results/mcmipl/mcmipl_YELP_STAR_s{0,1,2}.json`、`comparison/collect_results.py` 重扫得到的 `mcmipl_main_table.csv`  
> **重要底线（不可省略）**：**不得**在正式论文或对外材料中声称 **`seed=2` 与 `seed=0/1` 一样均为「满 `max_steps=50` 的正常训练终态」**。以下为**同一套指标定义**下的并排展示 + **探索性**三 seed 汇总，其中 **seed 2 的 RL 训练在约第 40 个大步处被中断**。

---

## 1. 发生了什么

- **`seed=0`、`seed=1`**：日志通过 `run_mcmipl.sh` 正常结束，`completed_RL_steps = 50`，`training_done = true`（且无「人工中止」脚注）。  
- **`seed=2`**：训练过程在约 **40** 个 RL 大步之后被 **终止**（非自然跑满 50 步）。  
- **技术细节**：杀掉 Python 后，`run_mcmipl.sh` 仍可能向日志 `tee` 一行 `=== DONE: YELP_STAR seed=2 ===`，**该行不能单独作为「满训完成」依据**。日志尾部已追加 **`TRAINING STOPPED BEFORE DONE`** 脚注；`collect_results.py` 已补丁：**若存在人工中止脚注则 `training_done` 强制为 false**。  
- **指标定义（三 seed 一致）**：表内数值来自 `collect_results.py` / `mcmipl_log_metrics.py`：**在历次「完整 eval」的均值行中选 SR@15 最大者**（与 `RL_model.py` 内部 `SR15_best` 逻辑一致）。**这不等于**「第 50 步终点的最后一次 eval」，尤其当训练未跑满时。

## 4. 为何不能写成「与 50 步等价」

1. **优化轨迹不同**：少训 10 步与「训满 50 步」在 RL 上不是同一实验单元。  
2. **检查点策略**：当前 `save_num=50` 下，**未在 50 步正常结束则没有本次 run 的正式策略存档**；JSON 中指标是 **历史 eval 最优**，不是最终一步权重在测试集上的结果。  
3. **学术表述**：将 40 步中断伪装为 50 步满训，属于**误导读者**；本报告**拒绝**采用该表述。
